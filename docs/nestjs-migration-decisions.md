# NestJS migration: decision log

Append-only log of decisions made while porting `backend/` (FastAPI) to `server/` (NestJS). Plan: `~/.claude/plans/i-want-to-rewrite-eager-hammock.md`. Contract and golden vectors: `docs/contract/`.

## Format
`YYYY-MM-DD · area · decision — why / what it costs`

## Decisions

- 2026-11-04 · strategy · Strangler, side by side on the same Postgres + Redis; no big-bang. — Keeps the frontend working and allows per-route-group cutover.
- 2026-11-04 · location · New `server/` beside `backend/`; `backend/` is deleted only after soak. — Easy diffing against the Python source.
- 2026-11-04 · ORM · Drizzle over Prisma/TypeORM. — Native pgvector (`cosineDistance`), SQL-like like the current SQLAlchemy `select()` code.
- 2026-11-04 · schema ownership · Alembic is frozen at head `41dfe2cad85a`; no new Alembic revisions. Drizzle schema is hand-written from `backend/app/models/*` and checked against the Alembic-built DB. — Two schema owners would drift.
- 2026-11-04 · `drizzle-kit pull` skipped · Pointing tools at the real dev DB needs `backend/.env`, which project rules forbid reading. A scratch DB `tijaratk_nest` was built from the Alembic migrations with explicitly passed throwaway env vars. — Costs nothing, keeps secrets untouched.
- 2026-11-04 · validation · zod everywhere (API bodies, LLM structured output). — One schema serves both.
- 2026-11-04 · queue · BullMQ replaces arq; nightly clustering is a repeatable job. Conversation lock keeps the same Redis key `conversation:{id}:lock`. — Python and Nest workers exclude each other during overlap.
- 2026-11-04 · test framework · Vitest (what Nest 12 scaffolds) instead of Jest. — Don't fight the scaffold.
- 2026-11-04 · verification data · `docs/contract/golden.json` (generated by `gen_golden.py` from the Python code) is the spec for pure logic, crypto and signatures. `openapi.json` is the route/shape contract.
- 2026-11-04 · eval parity · Model-dependent eval (`eval/fixtures.json`) is not recorded as golden; the pipeline is tested with mocked LLM responses instead. — The live model is nondeterministic and costs money.
- 2026-11-04 · real-data checks · Fernet round trip against a real `page_access_token` row is NOT done (needs the real `ENCRYPTION_KEY`). Wire compatibility is proven with Python-generated vectors in golden.json. Still open: run once against real data before cutover.

## Implementation decisions (phases 1-6, built 2026-11-04)

### Architecture
- 2026-11-04 · modules · One `AppModule` + a global `CoreModule` (DB / REDIS / QUEUE / SETTINGS providers) instead of a Nest module per domain. Domains are folders with a plain-function `service.ts` + thin controller. — Python had no DI either (`session` param); per-domain modules were pure ceremony. Revisit if domains need to be lazy-loaded or published.
- 2026-11-04 · DI · Every injection uses explicit `@Inject(TOKEN)`; no reliance on `emitDecoratorMetadata` (Vitest/esbuild doesn't emit it).
- 2026-11-04 · db handle · Services take `Db | Tx` as first arg (mirrors the Python `session` param). A transaction handle is a valid `Db`, which is how tests inject a rolled-back transaction into the whole app.
- 2026-11-04 · transactions · Controllers wrap mutations in `db.transaction(...)` (commit on success, the Python `await db.commit()`); the worker wraps lock -> pipeline -> send -> persist in one transaction.
- 2026-11-04 · errors · Global `DetailExceptionFilter` renders `{detail: ...}` (FastAPI shape); zod failures render FastAPI's 422 `{detail:[{loc,msg,type}]}`. Frontend error handling is unchanged.
- 2026-11-04 · serialization · API stays snake_case + ISO-8601 UTC (`...Z`); numeric columns keep the Python split: floats for product/order money in order reads, quantized strings for delivery fees and checkout-state.
- 2026-11-04 · money · `core/money.ts` does exact BigInt decimal math with ROUND_HALF_EVEN and "sum then round once" - verified against Python `Decimal` vectors (e.g. 0.05 x 0.5 = 0.02, not 0.03).
- 2026-11-04 · Fernet · Own 40-line implementation on `node:crypto` (spec-compliant, verified against Python-produced tokens) instead of the unmaintained `fernet` npm package. Legacy plaintext rows still pass through on read, like `EncryptedString`.
- 2026-11-04 · JWT · `jsonwebtoken`, same `{sub, exp}` claims/secret/alg: tokens minted by Python verify here and vice versa.
- 2026-11-04 · Twilio · official `twilio` package `validateRequest`; Meta HMAC over raw bytes with `timingSafeEqual`.

### Deliberate behavior differences from Python (all bug-fixes or hardening)
- 2026-11-04 · delivery routes · Python's `POST/PATCH/DELETE /delivery-areas` never called `db.commit()`, so (outside tests, which share one session) writes were rolled back on session close. The port commits. **Ask: did the dashboard ever expose delivery areas? (frontend/lib has no delivery module, so probably unnoticed.)**
- 2026-11-04 · tool dispatch · Handlers run in a savepoint. Python `COMMIT`ed after every action even on rejection, which could persist half-done work (e.g. `create_order` flips the cart to CHECKED_OUT, *then* fails delivery validation -> cart converted with no order). A rejected/failed action now rolls back its own writes; the `ai_actions` audit row is still written.
- 2026-11-04 · no mid-request commits · Python's `dispatch_action` committed mid-pipeline, so a later crash kept partial progress. Now the whole pipeline step is one transaction. Consequence: if the process dies after the Facebook send but before commit, the retry resends (same exposure as Python's send-then-commit order).
- 2026-11-04 · BullMQ `attempts: 1` · Matches arq (it only retries on an explicit `Retry`), avoiding duplicate Facebook sends.
- 2026-11-04 · redelivery idempotency · The worker's `message.intent IS NOT NULL` guard does NOT cover the tool-ordering and human-takeover paths (neither sets `intent`), so in Python a Meta redelivery re-ran them (e.g. a second cart add). The port also enqueues with `jobId = messageId` (+ 1h retention of finished jobs), so redeliveries within the hour are dropped at the queue for every path. Python's own test expecting a redelivery to enqueue again was deliberately not ported.
- 2026-11-04 · webhook body parsing · Express' JSON parser answers malformed bodies with 400 *before* the handler; Meta retry-storms on non-2xx. `/webhooks/meta` uses a raw-body parser so a garbage payload is acked 200 and recorded with `processing_error` (found by a ported test).
- 2026-11-04 · find-or-create merchant · `INSERT ... ON CONFLICT DO NOTHING` + re-select instead of the flush/rollback/re-query dance.
- 2026-11-04 · worker re-read · The worker re-reads the message and conversation *inside* the conversation lock, so a redelivery that waited on the lock sees the previous holder's result instead of acting on stale state.
- 2026-11-04 · generation prompt · `GENERATION_TASK_BLOCK` keeps the literal `{merchant_name}` placeholder exactly like Python (it was never substituted - the block is a `str.format` *value*). Looks like an upstream bug; fix deliberately in both when parity is no longer needed.

### Known gaps / follow-ups
- 2026-11-04 · scripts · `backend/scripts/*` (seed, reset_db, reembed_products, run_eval, view_orders, ...) and `backend/eval` are NOT ported; they are dev/ops tooling, and eval hits a live model. They keep working against the same DB. Port `reembed_products` + `seed` when `backend/` is removed.
- 2026-11-04 · OpenRouter streaming quirk · PORTED. `DEEPSEEK_MODEL` is a `~deepseek/...-latest` route, which streams SSE even with `stream=false`. `engine/clients.ts::readCompletion` takes the SDK's raw `Response` (`asResponse()`; retries/auth/APIError still handled by the SDK) and aggregates SSE chunks or parses JSON, whichever arrives. Covered by unit tests and a live run against a fake streaming server.
- 2026-11-04 · pm2 · `ecosystem.config.js` is intentionally untouched (a plain `pm2 start` there must not launch an unbuilt/unconfigured Nest app or a second worker). The Nest apps live in `ecosystem.nest.config.js`; running both workers at 03:00 can duplicate auto-learning examples (earlier note claiming it was harmless was wrong).
- 2026-11-04 · settings · Required/optional matches `backend/app/core/config.py` (no defaults for DB, models, provider URLs, JWT secret); booleans parse like pydantic (case-insensitive true/false/1/0/yes/no/on/off). `DATABASE_URL` is an extra alternative to the `POSTGRES_*` parts.
- 2026-11-04 · request coercion · pydantic lax mode would accept numeric strings / `"true"`; zod here does not. Checked `frontend/app/demo/{actions.ts,product-catalog.tsx}`: the dashboard sends real JSON numbers (`parseFloat`/`parseInt`) and booleans, so no coercion was added. Other API clients sending strings would now get 422.
- 2026-11-04 · rate limiter · Same keys/tiers/fail-open as Python (`rl:{ip}:{window}`, 429 + `Retry-After`). Found live: inside Nest's middleware mount `req.path` is not the full path, so `/health` was not exempt; it now uses `originalUrl`. As in Python the counter is per IP across all paths (the demo tier only changes the threshold).
- 2026-11-04 · structured-output schemas · `docs/contract/gen_golden.py` now also dumps pydantic's `model_json_schema()` for intent/extraction/reply/action; `json-schema-parity.spec.ts` asserts the zod-generated schemas match property-by-property (types, bounds, enums, required). `$schema` is stripped from ours to match pydantic's output.
- 2026-11-04 · cron timezone · arq's `cron(hour=3)` vs BullMQ `0 3 * * *` (server local time). Confirm the box timezone before relying on 03:00.
- 2026-11-04 · agglomerative clustering · Own O(n^2) implementation (parity-tested against sklearn on 9 seeded cases). Fine for the nightly `limit=1000` batch.
- 2026-11-04 · `Message.created_at` in a single transaction · Postgres `now()` is the transaction start time, so rows inserted in one request share a `created_at`; history ordering still excludes the in-flight message by id, as in Python.
- 2026-11-04 · float formatting · A few user-visible strings reproduce Python float formatting (`pyFloat`, `fmt0`): e.g. prices render as `100.0 جنيه`. Kept for visible parity; tidy up later if desired.
- 2026-11-04 · still open before cutover · (1) decrypt a real `page_access_token` row with the production `ENCRYPTION_KEY`; (2) shadow-compare read endpoints against live Python responses; (3) replay recorded Meta/Twilio payloads; (4) re-check Nginx routing/ports and flip route groups one at a time.
